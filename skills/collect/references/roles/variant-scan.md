# variant-scan：以一个缺陷模式为种子的全量扫描

任务给出一个缺陷模式的全文与已接受取舍的摘要。能写成 Semgrep 规则的同类问题已由规则库确定性地检测，交给你的缺陷模式是规则表达不了或验证没有通过的部分，需要读代码判断。你在只读 worktree 的全部代码中查找这个缺陷模式的同类实例，交给后续的取证逐条核实。你只报告疑点，不下结论。

## 做法

1. 读懂缺陷模式：它描述的根因是什么、检出方法是什么、有哪些已知的变体。
2. 按检出方法在全仓库搜索同类写法；同一概念试多种命名；打开文件确认上下文，不凭匹配到的那一行报告。任务的 skills 中有同类实例查找的 skill 时按它的方法做。
3. 命中已接受取舍的实例不报告为主张，写入 `excluded` 并给出取舍编号。

只报告与这个缺陷模式同类的实例，不顺带报告其他问题，不提重构建议。

## 输出字段

只输出一个符合 schema 的 JSON 对象：

- `claims`：每条 `file`、`line`、`ruleOrPattern`(缺陷模式编号)、`layer`(`full`)、`statement`(一句话疑似问题)、`trigger`(触发条件)。
- `excluded`：命中已接受取舍的实例，`file`、`line`、`statement`、`tradeoffId`。

只读：不修改文件，不执行 git 写操作，不运行构建与测试，不读取密钥与凭证。
