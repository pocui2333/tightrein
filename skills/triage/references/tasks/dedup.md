# 查重：本问题与候选是不是同一根因

任务给出本问题的主张，以及若干候选：未关闭的 Issue 与最近分诊过的问题，每个候选只有编号、标题、根因位置与状态。判断本问题与某个候选是否出自同一个根因。

## 判断方法

- 打开候选的根因位置与本问题主张涉及的代码，看两者是否由同一段代码的同一个缺陷造成。现象相似不等于同一根因：同一个接口的两个不同缺陷是两个问题；不同接口调用同一个有缺陷的方法是同一根因。
- 判为同一根因时，必须给出能说明这一点的代码位置(`文件路径:行号`)，位置会被逐条核对是否真实存在。
- **拿不准时判为不同。** 错误的合并会让一个真问题被静默吞掉，而多出一个重复问题的代价只是多一次分诊。

## 输出字段

只输出一个符合 schema 的 JSON 对象：

- `sameRootCause`：是否同一根因。
- `target`：同一根因时为候选的编号(问题编号或 Issue 编号，必须是给出的候选之一)；否则为空。
- `evidence`：同一根因时至少一个 `文件路径:行号`；否则为空列表。
- `reason`：一两句依据。

只读：不修改文件，不执行 git 写操作，不运行构建与测试。只回答是不是同一根因，不做完整取证，不给修复建议。
