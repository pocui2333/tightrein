# 本机启动与页面检查的做法

这些做法来自一次实际跑通的运行，由本工具的验证过程执行；这里写给需要理解验证结果、或者手动排查的 agent 与用户。

## 两种启动模式

- **api 模式**：只启动后端，用于接口类复现检查与接口浅跑。端口取 `localRun.ports.api`，应与日常开发常用的端口不同，避免和用户自己正在运行的服务冲突。
- **page 模式**：启动后端与前端，用于页面类复现检查与页面巡检。端口取 `localRun.ports.backendForPages` 与 `localRun.ports.frontend`，按前端开发服务器实际代理的后端端口配置。
- 需要页面时优先用 page 模式；page 模式的端口被占用时退回 api 模式，页面类检查记为未验证，并提示用户空出端口后重跑。

## 启动什么由扩展决定

- 启动命令、工作目录、非敏感的环境变量、端口、成功与失败信号、不在本机启动的服务、迁移文件的路径模式都由 `local-run` 扩展给出。本工具只按启动计划执行，不含任何项目或技术栈的启动知识。
- 没有 `local-run` 扩展时不启动任何服务，需要本机服务的检查一律记为未验证，只执行静态类检查。
- 连接配置由被测程序自己读取：本工具、扩展与 agent 都不读取任何配置文件与凭证，也不连接数据库。

## 启动前

- **先检查端口**：端口在监听时，只有进程编号与命令行都和本工具上一次记录的一致，才算本工具遗留的进程，终止后继续；其他程序占用的端口一律不动，不强行启动。
- **迁移只看 diff**：修复是否改动了迁移文件从 diff 判断，不连库查询。没有改动时启动不会执行新迁移；有改动时启动会把新迁移应用到测试库，先向用户说明将执行哪几条、能否撤销，确认后再启动。修复前复现在未修改的代码上运行，不会有新迁移。
- **验证一律使用本工具启动的服务**：即使用户那边已经有服务在跑，也不复用，保证每次验证的条件一致。

## 就绪判断

- 同时匹配成功信号与失败信号。只等成功信号的话，进程崩溃时会一直静默等到超时。
- 进程提前退出、出现失败信号或超过 `localRun.readyTimeoutSeconds` 都判为启动失败，需要该服务的检查记为未验证，原因附日志中匹配到的失败行；不重试。
- 成功信号出现后再请求一次就绪地址，确认端口确实可达。

## 页面检查

- 路由从路由清单(`page-routes` 扩展)读取，不要猜。猜错的地址往往是一张没有报错的空页面，看起来像功能坏了，其实是地址错了。
- 优先点击导航进入页面，而不是直接跳转地址：这既是真实用户的路径，也避开了猜地址。
- 同名按钮要限定所在的容器，否则可能点到表格行里的同名按钮。
- 每个页面脚本都要监听控制台错误、未捕获的页面异常与失败的请求：控制台监听抓不到未捕获的异常，页面异常要单独监听。
- 加载跳变一类时序问题要按固定间隔采样中间状态，只看最终状态看不出来。
- 需要在测试库中创建真实数据才能触发问题时，停下来问用户。

## 截图必须查看

- 布局问题(遮挡、错位、溢出)只能从截图发现，DOM 查询发现不了。截图交给截图评审，评审无法判断或工具不能读图时由用户查看。
- 截图是证据，不是留档：截了不看，等于没有验证。

## 三档结论

| 档 | 含义 | 写法 |
|---|---|---|
| 验证通过 | 执行了，有证据 | 附上证据：命令与输出、复现检查前后的结果、截图 |
| 弱证据 | 执行了，但前置条件不满足 | 说清为什么弱，例如列表中没有能触发问题的数据 |
| 未验证 | 没有执行 | 逐条写出本应验证的具体行为与原因，不能只写「未做页面测试」 |

把弱证据写成验证通过，等同于伪造检查通过。

## 收尾

验证结束(包括出错与中断)时停止本次启动的全部进程组，等待 `localRun.stopTimeoutSeconds` 后仍未退出的强制结束；日志保留在验证报告目录的 `services/` 下。进程意外中断没有收尾时，下一次启动由遗留进程的识别处理。
