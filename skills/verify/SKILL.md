# verify

验证只做独立于写代码模型的检查，由确定性程序完成，不由 agent 判断结果。修复前复现、项目检查与修复后复现已在修复内部完成(修复第 5、7 步)，验证不再重复。本 skill 只说明何时调用哪个命令、如何读结果与处理等待用户的情况。**不要自己启动服务、不要自己写检查脚本，也不要把没有执行的检查说成通过。**

## 命令

```
tightrein verify local <编号> [--confirm-migration]
tightrein verify screenshots <编号> --ok | --issue <说明>
tightrein verify staging <编号>
```

| 命令 | 何时用 | 前置条件 |
|---|---|---|
| `verify local` | `fix done` 之后(PR 阶段的本机检查) | Issue 进行中、处于合并前验证阶段；修复评审通过且之后没有新改动 |
| `verify screenshots` | PR 阶段检查停在「截图待查看」时 | 最近一次检查在等待截图查看 |
| `verify staging` | 部署跟踪发现包含合并提交的部署之后(编排自动调用) | Issue 完成且等待部署后确认(头信息 `phase` 为 `deploy-check`)；没有配置部署来源时合并后经过观察期才有部署记录 |

## PR 阶段做什么

| 检查 | 运行条件 |
|---|---|
| 其他问题的回归 | 总是：采用修复第 7 步的结果(`otherRegressions`)，需要服务的接口与页面类在启动服务时补跑 |
| 本机启动服务跑接口测试 | 项目配置了本机启动(`local-run`)且改动涉及接口：本 Issue 与相关的接口类复现检查、受影响接口的 api-fuzz 浅跑 |
| 截图评审 | 改动涉及前端且配置了页面检查(`page-routes` 或工作区的 e2e 用例)，并配置了本机启动 |
| 项目 CI 的必需检查 | PR 创建后由 `release track` 读取(没有必需检查时跳过)，失败时不自动合并并进收件箱 |

条件不满足的检查写在交接文档的 `skipped` 中。不对 PR 的 diff 单独跑静态巡检。

## 解读结果

读 `data/verify/<编号>/<日期>-<阶段>/report.md`(交接文档为 `verify-<阶段>-<编号>.json`)。每个检查项是四种结果之一：

| 结果 | 含义 |
|---|---|
| 验证通过 | 执行了，满足通过条件，并保存了证据 |
| 弱证据 | 执行了，但前置条件不满足(例如页面上没有能触发问题的数据) |
| 未验证 | 没有执行：端口被占、服务启动失败、依赖不在本机启动的服务；报告写明本应验证的行为与原因 |
| 失败 | 执行了，结果不满足通过条件 |

**弱证据不是验证通过。** 把弱证据或未验证说成通过，等同于伪造检查通过。向用户转述时逐条列出弱证据与未验证的条目。

- PR 阶段：有失败项时退回待修，报告作为下一次 `fix start` 的输入，连续失败达到上限时转待决定；否则进入提交阶段；「等待用户」见下一节。
- 部署后确认(按问题来源，交接文档的 `confirmations`)：接口与页面类复现检查对目标环境重放；静态类与测试类对部署 commit 重跑；来自服务端日志(错误追踪、监控平台)或检查无法执行的问题看观察期(`thresholds.verify.observationHours`)内是否再出现。全部通过时 Issue 最终完成、关联问题同步；有回归时先提撤销 PR(待确认操作，由用户决定是否合并)，Issue 退回待修；其余等下次定时运行继续确认。

## 等待用户时

- **端口被占用**：本工具不会终止不属于它的进程。告诉用户是哪个端口，请用户空出端口后重跑；页面类检查会先记为未验证。
- **迁移待确认**：修复改动了迁移文件，启动服务会把新的迁移应用到测试库。向用户转述将执行的迁移条目、能否撤销与撤销方式，用户同意后执行 `verify local <编号> --confirm-migration`。
- **截图待查看**：截图评审给出「无法判断」或所用工具不能读取图片。请用户查看报告中列出的截图，只判断遮挡、错位、溢出；无问题执行 `verify screenshots <编号> --ok`，有问题执行 `verify screenshots <编号> --issue <说明>`(计为失败)。
- **撤销 PR 待确认**：部署后确认发现回归时生成。向用户转述回归现象(报告中的失败项)，由用户确认是否提撤销 PR 并合并。
- **需要创建真实数据**：复现检查或巡检需要在测试库中创建记录才能触发问题时，先问用户，不要自己决定。

本机启动的做法与注意事项见 `references/local-run.md`。
