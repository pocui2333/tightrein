# 13. 规模档与处理标签

不计算数值优先分。分诊给出规模档与处理标签，修复开始前按复杂度分配轮数与预算；三者都由规则得出，不是对问题或任务的打分。

## 13.1 规模档

分诊按取证评估中预估改动的文件数与行数(不含测试文件)给出规模档：文件数与行数都不超过某档上限时取该档。

| 档 | 文件 | 行 |
|---|---|---|
| 微 | ≤1 | ≤30 |
| 小 | ≤3 | ≤100 |
| 中 | ≤10 | ≤500 |
| 大 | ≤30 | ≤3000 |
| 超限 | 超出大档 | |

各档的门槛是配置项(`thresholds.tiers.<档>.maxFiles`、`maxLines`，architecture/01 5.2)，表中数值为默认值。规模档与任务类型决定修复的通道
(5.2，[redesign/05-fix.md](../redesign/05-fix.md))；单个 PR 的改动量上限 `thresholds.change` 缺省与中档一致。

## 13.2 处理标签

按决策树(参照 SSVC)由判定、严重度、规模档与价值判断直接给出处理标签，按顺序取第一条全部条件都满足的规则
(`triage.treatment.rules`，条件省略表示不限，项目整体覆盖)。缺省规则：

| 条件 | 处理标签 |
|---|---|
| 价值判断为不该修 | 不修 |
| 严重度 P0 | 立即修 |
| 严重度 P1 且判为确认成立 | 立即修 |
| 价值判断为暂不修 | 观察 |
| 严重度 P1、P2 | 排期修 |
| 严重度 P3、规模为微或小、价值判断为该修 | 排期修 |
| 其余 | 观察 |

- 去向按处理标签映射(3.6)：立即修、排期修提 Issue；观察为暂不修；不修为已接受的取舍。判为不成立、证据不足与转人工的不进入决策树。
- `issue list` 按处理标签(立即修在前)、严重度、创建时间排序；运行摘要的等待事项中立即修的置顶，再按严重度排序。
- 预估改动触及受保护文件的 Issue 标注「需要先与代码作者讨论」。

## 13.3 任务复杂度

分诊与修复开始前，为任务估一个复杂度，用来分配轮数与预算：

| 复杂度 | 条件 | 分诊各角色的上限 | 修复预算 |
|---|---|---|---|
| 低 | 单一接口或单一方法、有堆栈、根因位置明确 | `stages.triage.roles.<角色>.limits.low` | `stages.fix.budget.low` |
| 中 | 涉及多个文件或跨前后端 | `stages.triage.roles.<角色>.limits.medium` | `stages.fix.budget.high` |
| 高 | 涉及权限、数据归属、并发，或者没有堆栈 | `stages.triage.roles.<角色>.limits.high` | `stages.fix.budget.high` |

- 复杂度只决定轮数与预算。各角色用哪一档模型按角色固定(9.6)；修复走哪条通道由任务类型与规模档决定(5.2)，是否做深度评审由 5.8 的
  风险判定决定。
- 复杂度的判定条件与各档的上限都是配置项(architecture/01 5.1)，不写在代码中。
- 任务实际的耗时、token 与费用记入环节效益(14.2)，按通道与模型统计(8.3)。
