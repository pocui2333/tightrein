# 接入

新项目第一次使用时，工作区先处于接入阶段：系统识别项目、补齐配置、向用户提问，并在各处明确显示「正在配置」。

## 1. 阶段

| 阶段 | 含义 | 能做的事 |
|---|---|---|
| 接入中 | 正在识别项目、补配置、等用户回答 | 只做只读的事：识别技术栈、试连接平台、在基准版本上自检检查命令；不修代码、不提 PR、不建 Issue |
| 运行中 | 接入清单全部完成 | 按配置运行；自主决定、自动合并等由各自的开关控制 |

阶段记录在数据库中，并体现在工作区的 `onboarding.md`。

## 2. 接入清单

`workspaces/<项目>/onboarding.md` 使用交接文档格式中的进度类型。每一项是一个复选框，注明由系统自动完成、需要用户回答，或失败待处理；
结论一节写明完成了几项、还有几项需要回答、几项失败。清单项包括：识别技术栈；检查命令在基准版本上通过；项目约定(分支、提交、PR)的识别结果待确认；
接口描述(自动导出或 AI 起草)待确认；各平台(错误追踪、日志、监控、部署)是否接入及试连接结果；测试账号；角色能力表等。

## 3. 提问与显示

- 需要用户回答的问题都进入待用户决定的收件箱(09-loop.md 第 4 节)，每个问题附推荐答案与理由，可以一次回答多个。
- `tightrein status` 显示「<项目>：接入中，还差 N 项需要回答」；每天的汇总中有「接入中的项目」一节。

## 4. 回答方式

- 终端：`tightrein project init` 逐项提问，有推荐答案时直接回车即采用。
- 对话：通过 loop skill 列出待回答的问题，用户用自然语言回答，由 agent 写回配置。
- 文件：在 `onboarding.md` 中勾选或直接修改 project.yaml，下次运行时重新检查。

## 5. 转为运行中

清单全部完成、已配置的来源全部试连接成功、检查命令在基准版本上通过后，转为运行中。
