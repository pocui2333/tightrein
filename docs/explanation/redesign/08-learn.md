# 学习

学习模块记录每次运行的结果，把经验与修好的缺陷沉淀下来，并为系统与用户提供决策依据。它不训练模型，也不自动修改自身。

## 1. 组成

| 功能 | 做法 |
|---|---|
| 环节效益统计 | 程序记录每次模型调用的费用与结果；按通道、按模型统计一次通过率、每个修复的费用、被撤销的比例 |
| 周报 | 程序生成 |
| 经验总结 | 只在出问题时写：评审驳回、修复失败、被撤销、用户纠正。每条经验带来源与过期时间，长期未被使用的自动清除，避免记忆积累噪音(Reflexion 类经验复用有效，但需要清理机制) |
| 缺陷变规则 | 修好一个缺陷后生成一条 Semgrep 规则，并用原补丁验证：修复前的代码命中、修复后的代码不命中、全仓库误报在可接受范围内，才收入规则库；之后同类问题由程序确定性地检测(参照 KNighter) |
| 知识库与检索 | 全文检索与 MCP 接口 |
| 链路健康 | 程序检查各环节是否正常运行 |
| 自我改进 | 只做建议，不自动修改：从失败中归纳对提示词或配置的修改建议，附评测用例的对比结果，由用户批准后才生效；评测必须包含未参与改进的用例，评分以确定性检查为主 |

## 2. 评分、奖励与惩罚

- **不对模型做奖励或惩罚**：不在提示词中许诺奖励或威胁惩罚(研究表明这类提示对有难度的任务没有稳定效果)；tightrein 调用现成模型，
  也没有用奖励训练模型的通道。
- **分数不作为模型的目标**：不在提示词中告诉模型会按什么评分，评分也不只看测试通过率，防止模型为通过评分修改测试或针对测试数据写死特殊处理。
  评审专门检查是否只针对测试数据写了特殊处理。
- **评分只作为衡量手段**，以确定性的结果为主，不以模型打分为主；分数给系统与用户看，不放进模型的提示。

| 评分 | 得出方式 | 用于决定 |
|---|---|---|
| 一次通过率(按通道、按模型) | 复现测试与检查第一轮即通过 | 写代码的模型是否够用，是否升级 |
| 修复是否真正有效 | 合并后未被撤销，部署后确认问题不再出现 | 各通道与各环节的真实质量 |
| 分诊准确率 | 判为成立的，复现测试是否确实在修复前失败；判为误报的，之后是否再出现 | 证伪复核是否扩大范围 |
| 用户纠正次数 | 驳回计划、关闭 Issue、撤销合并 | 自主决定的门槛是否收紧 |
| 每个修复的费用 | 程序统计 | 预算与通道划分 |

- **分数驱动系统层面的控制措施**：例如某个模型的一次通过率持续偏低时建议换用更强或其他模型；连续失败时停下转待决定；用户频繁纠正某类决定时
  改为交用户确认。凡是改配置的调整，都先交用户批准。
- 原设计中用于排序的数值优先分不再使用(分诊改为决策树，见 03-triage.md)。
