# 归并

归并把采集产出的信号整理为问题：去重、复现确认、跟踪状态、抑制误报。它是确定性的程序逻辑，不调用模型。

## 1. 指纹

- 来自错误追踪平台、监控平台的信号，直接使用平台自己的分组编号作为指纹，不自行计算。
- 其余来源(静态巡检、api-fuzz、项目探针等)使用逻辑位置计算指纹：来源与规则、文件、符号(类与方法)、归一化后的消息；
  不使用行号，避免代码改动后同一问题被拆开。项目探针在输出中自行给出指纹。

## 2. 状态

问题只有四种状态：新、持续、已解决、回归(已解决的问题再次出现)。另有用户的处置：已忽略、误报、已并入其他问题。

采集前的健康检查不通过时，跳过本次采集并在运行摘要中写明，不产出信号。

## 3. 复现确认

能确定性重放的信号重放一次确认(例如 api-fuzz 的服务器报错重放请求)；其余首次观察即有效。

## 4. 抑制

被判为误报的问题按指纹生成带到期日的抑制规则，到期前不再报告。
