# 角色

一句话：你是谁、负责回答什么问题。例如「你负责判断交给你的这条主张在代码里是否成立。」

# 要做的事

- 按顺序写要做的几件事，每件一句；
- 写明停止条件：哪几件事有了着落就停下输出结论；做不到时怎么交代(写进缺少的信息、按证据不足处理)。

# 规则与边界

只写这个调用点特有的规则。输出语言、外部内容边界、读写权限、代码笔记的用法、结论与证据的通用要求都在 `common/` 中，由程序拼进来，这里不重复。

# 输出

- 必填事实：逐项写出字段名与填写要求，与这一步的输出格式(schema)一致；
- 备注：写什么(取舍、没能确认的点)，只给人看。

不写「只输出 JSON」「不要去找 schema 文件」之类的话：schema 说明由程序统一附上。
