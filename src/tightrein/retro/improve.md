# 改进规范

拿复盘记录(`data/retro/`)去改 tightrein 时必须遵守，避免越修越多针对性的补丁。与「实现原则」第 3 条(通用，不写特例)一致。

1. **先归类**：每条记录先对到协议层的某一项(边界、交接、时限、资源、恢复、安全、记录、调度……)；对不上的，说明协议层缺了一项，先补协议再修。
2. **先通用兜底**：能在协议层或配置层解决的，不在某个步骤里加特判；只有确实只在这一步发生的问题，才改这一步。
3. **能配就不写死**：只是阈值或开关的问题，改 settings 中的取值，不改代码。
4. **一次只改一类**：一次改动只处理一类记录，并在提交说明中写明对应的记录编号。
5. **用数据验收**：改完后用量化数据(token、耗时、轮数)对比改前改后，没有变好就回退。
6. **改完就关**：同一类的记录一并关闭(`tightrein retro close <编号> --done`)，不留修了一半的状态。
