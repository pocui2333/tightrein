# 方法文档的统一格式

每种项目探针方法写一份 `NN-<名称>.md`(编号递增)，按下面十一个小节写，顺序固定，没有内容的小节写「无」。
每个小节都对应 tightrein 已有的一处约定，写的时候以这些约定为准，不自行发明字段：

| 小节 | 写什么 | 以哪处约定为准 |
|---|---|---|
| 介绍 | 这种方法发现什么问题，适用于什么样的项目 | 无 |
| 实现方式 | 怎么取得数据、怎么判定异常(规则、阈值、比较方式) | 只读：采集阶段只查不写(`protocol/boundaries.md`) |
| 运行模式 | 触发方式与频率、检查的时间窗口、只读要求、跨次运行保存的状态 | `controls."collect.project_probes".probes[]` 的 `every`；输入的 `window`、`state` |
| 架构设计 | 探针由哪些部分组成，与 tightrein 的交互(谁调用、经什么传入传出) | `source.py`：标准输入一个 JSON，标准输出一个 JSON |
| 代码排版 | 文件放在哪、叫什么、程序结构(入口、读取、判定、输出各在哪一段) | 工作区 `scripts/` 下，一个探针一个文件 |
| 输入格式 | 探针收到的数据(tightrein 给的输入 JSON 与探针自己读取的数据源) | `README.md` 的「契约」中的输入 |
| 输出格式 | 交回的信号：每个字段怎么取值(location、symptom、evidence、severityHint、fingerprint 等) | `output.schema.json` |
| 输出文档 | 运行后留下的记录(运行记录、日志)以及在哪里查看 | 运行目录的 `11-collect.project_probes-handoff.json` 与 `-raw/` |
| 交接内容 | 交给下一阶段(去重、评估)的是什么，评估据此要判断什么 | 信号(`collect/common/signals.py`)；指纹为「探针名:fingerprint」 |
| 选用条件 | 项目需要具备什么才能用：数据源、权限、配置项；不满足时怎么办 | 接入清单 `setup.json`、`sites.json`、`secrets.json` |
| 去重 | 同一个问题没有变化时不重复报：用 state 记住已报过的问题与它当时的情况，有变化(再次发生、加重)才再报 | 输出的 `state`，下次原样放进输入 |

## 写法要点

- 探针只从外部只读观察：调只读接口、读日志平台、读项目自己写的记录文件；不改数据，不登录服务器。
- `fingerprint` 只由「检查项:对象」组成，不带时间、数量、随机值，否则同一个问题每次都成了新问题。
- `evidence` 写可核对的事实(数值、时间、查询与结果)，不写凭据与个人信息；写出前经 `helpers.redact`。
- 需要凭据时在登记里写 `secrets`(secrets.json 中的条目名)，脚本里用 `helpers.secret(条目名)` 读；没登记的读不到。
- 探针失败(退出码非 0、超时、输出不合格)时本次作废、状态不保存，下次到期重试；不要在探针里吞掉错误输出空结果。
